# Shopping-bag accessible quantity parity

Private bounded accessible-navigation repair based on 2c55e762dcf88bc9565b1dc457321692efab03ef. The existing visible badge summed item quantities, but its accessible link label counted distinct design lines. A two-line synthetic bag with quantities three and two therefore visibly showed five while announcing two. Header now derives one quantity total for both presentations. Empty-bag naming and badge omission remain unchanged; cart validation, pricing, inventory, payment, storage and quantity mutation are untouched.

The DOM regression failed with actual Shopping bag (2) versus expected Shopping bag (5) before the repair. Coverage verifies hydration, increment, line removal and empty state. Native Edge cases at 1280 and 390 widths additionally verify persisted quantity after reload, repeated removals and empty-state reload, using synthetic local-only designs. No live commerce or customer data is involved.

This is partial accessibility/discovery evidence, not full parent acceptance, manual screen-reader or physical-device qualification, production publication, or held guided-design/rollup/packaging work.

The first aggregate frontend run found one test-harness inventory failure: the new direct DOM-null assertion changed the existing historical strict-null assertion census. The new assertion now uses equivalent boolean identity with a diagnostic message; the original census and all original assertions remain unchanged. The failed log is retained. This alters no application behavior or test criterion.
